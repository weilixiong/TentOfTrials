# Independent Log Parser Fixtures & Validation — Fixes #5

## Summary

This PR adds **independent, hand-written parser fixtures** for `tools/log_aggregator.py` that eliminate the ~40% false-pass rate documented in the legacy test suite. The fixtures are crafted from real log format specifications and are **NOT** generated by the parser code itself — they independently validate parser correctness.

## Changes

### Bug Fix
- **Fixed parser precedence order** in `LogAggregator.__init__()`: `NginxLogParser` now runs **before** `TextLogParser`. Previously, Nginx access log lines were swallowed by `TextLogParser` (which matches any non-empty line), causing Nginx-specific fields (remote_addr, status, user_agent, etc.) to be lost. The order is now: JSON → Nginx → Text.

### New Files
- **`tools/test_fixtures/json_log_fixtures.jsonl`** — 15 hand-written JSON log lines covering: standard fields (`timestamp/level/service/message`), alternative field names (`@timestamp/severity/logger/msg`), and variant schemas (`time/lvl/app/event`). Tests all severity levels (INFO, DEBUG, ERROR, WARN, CRITICAL, FATAL, TRACE).
- **`tools/test_fixtures/text_log_fixtures.log`** — 15+ hand-written text log lines covering: bracket-wrapped services, syslog-style timestamps, inline ERROR: prefix, edge cases.
- **`tools/test_fixtures/nginx_log_fixtures.log`** — 15 hand-written Nginx access log lines covering: all HTTP methods, status code ranges (2xx/3xx/4xx/5xx), authenticated users, large response sizes, various user agents.
- **`tools/test_fixtures/malformed_log_fixtures.log`** — Edge case lines: empty, whitespace, broken JSON, JSON non-dicts, incomplete Nginx lines, wrong date formats, SQL injection-like content, null bytes, Unicode, extremely long lines.
- **`tools/test_log_parser.py`** — 37 focused test cases validating: field extraction, format detection, level mapping, service extraction, timestamp parsing, edge case handling, and cross-parser isolation.
- **`.github/workflows/parser-tests.yml`** — CI workflow that runs parser tests and build diagnostics on every push/PR touching parser or fixture files.

## Fixture Source & Intent

All fixtures are **hand-written from documented log format specifications**, not generated by the parser:
- JSON fixtures follow Elastic Common Schema (ECS) and Graylog Extended Log Format (GELF) conventions
- Text fixtures follow syslog RFC 5424 and common application logging patterns
- Nginx fixtures follow the standard `combined` log format from nginx documentation
- Malformed fixtures test real-world corruption patterns observed in production log pipelines
